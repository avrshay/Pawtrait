--------------------------------------------------------------------------------
HEADERS (auth middleware)
--------------------------------------------------------------------------------

Send **x-user-role** and **x-user-id** as real **HTTP headers** (Postman → Headers tab),
not only as URL query parameters. The server reads **req.headers["x-user-role"]** etc.

Gallery GET routes do not require headers.

--------------------------------------------------------------------------------
ONLY-ADMIN / STAFF — is x-user-id required?
--------------------------------------------------------------------------------

  • Gallery POST / PUT / DELETE  →  x-user-role: admin only (no x-user-id check)
  • Orders PUT / DELETE          →  x-user-role: admin OR manager (authorizeSelf skips id match for staff)
  • Orders GET / (all orders)    →  admin OR manager only

The URL path identifies the resource (e.g. /orders/2/1 = user 2, order 1). For role
**user**, **x-user-id** must match **:id** on routes that use authorizeSelf.

GALLERY (mounted at /gallery)
--------------------------------------------------------------------------------

1) List all catalog / gallery products
   Method: GET
   URL:    http://localhost:3000/gallery
   Body:   (none)

2) Get one product by id
   Method: GET
   URL:    http://localhost:3000/gallery/1
   Body:   (none)

3) Create product (admin only)
   Method: POST
   URL:    http://localhost:3000/gallery
   Headers (required):
     x-user-role: admin
   Headers (not used by auth — optional):
     x-user-id: (omit or any value; server does not check it on gallery writes)
   Body (raw JSON), example:
   {
     "name": "new_mug",
     "original_pet_image_url": "http://localhost:3000/images/clients/dog1-original.jpg",
     "custom_product_image_url": "http://localhost:3000/images/catalog/products/cup-design-dog1.png",
     "price": 45
   }

4) Update product (admin only)
   Method: PUT
   URL:    http://localhost:3000/gallery/1
   Headers (required):
     x-user-role: admin
   Headers (not used by auth — optional):
     x-user-id: (omit or any value)
   Body (raw JSON), example:
   {
     "name": "designed_cup",
     "original_pet_image_url": "http://localhost:3000/images/clients/dog1-original.jpg",
     "custom_product_image_url": "http://localhost:3000/images/catalog/products/cup-design-dog1.png",
     "price": 55
   }

5) Delete product (admin only)
   Method: DELETE
   URL:    http://localhost:3000/gallery/1
   Headers (required):
     x-user-role: admin
   Headers (not used by auth — optional):
     x-user-id: (omit or any value)
   Body:   (none)

ORDERS (mounted at /orders)
--------------------------------------------------------------------------------

Path params:
  :id       = user id (owner of the orders)
  :orderId = order id

5b) List all orders (admin / manager dashboard)
   Method: GET
   URL:    http://localhost:3000/orders
   Headers (required):
     x-user-role: admin   OR   manager
   Body:   (none)
   Response: JSON array of order headers { orderId, userId, status, createDate } for every user.
   Note: role "user" receives 403 on this route.

6) List all orders for a user
   Method: GET
   URL:    http://localhost:3000/orders/2
   Headers (example — regular user viewing own orders):
     x-user-role: user
     x-user-id:   2
   Headers (example — admin):
     x-user-role: admin
   Body:   (none)

7) List line items for one order (user must own that order unless admin/manager)
   Method: GET
   URL:    http://localhost:3000/orders/2/1
   Headers (example — user 2 viewing own order 1):
     x-user-role: user
     x-user-id:   2
   Headers (example — admin):
     x-user-role: admin
   Body:   (none)
   Response lines include: id, orderId, productId, quantity, petImageUrl (customer pet photo for that line).

8) Create a new order (checkout) for user :id
   Method: POST
   URL:    http://localhost:3000/orders/2
   Headers (example — user creating for self):
     x-user-role: user
     x-user-id:   2
   Headers (example — admin creating for user 2):
     x-user-role: admin
   Body (raw JSON), example:
   {
     "items": [
       { "productId": 1, "quantity": 2, "petImageUrl": "http://localhost:3000/images/clients/my-pet.jpg" },
       { "productId": 2, "quantity": 1, "petImageUrl": "http://localhost:3000/images/clients/my-pet2.jpg" }
     ]
   }
   Notes:
   - Each productId must exist in the gallery catalog (products mock data).
   - Each line must include petImageUrl (non-empty string): URL/path to that line's pet photo (upload is client-side; API stores the reference).
   - Order status is set to "processing" by the server; order row has no quantity field.
   - Per-line quantity is stored on each order item.

9) Update order header (admin or manager only — not user)
   Method: PUT
   URL:    http://localhost:3000/orders/2/1
   Headers (required):
     x-user-role: admin   OR   manager
   Headers (not required for admin/manager — authorizeSelf does not compare x-user-id to :id):
     x-user-id: (omit for staff; required only when using role "user", which is blocked here anyway)
   Body (raw JSON) — all fields optional except merged row must keep valid status; example:
   {
     "status": "completed"
   }
   Other optional fields: "userId", "createDate" (ISO date string if used)

10) Delete order and all its line items (admin or manager only — not user)
    Method: DELETE
    URL:    http://localhost:3000/orders/2/1
    Headers (required):
      x-user-role: admin   OR   manager
    Headers (not required for admin/manager — same as PUT above):
      x-user-id: (omit for staff)
    Body:   (none)

PAYMENTS (mounted at /payments in server.js — requires routes/paymentRoutes.js to register routes)
--------------------------------------------------------------------------------

Ensure **routes/paymentRoutes.js** mounts **POST /start** and **POST /webhook** on this router
(an empty routes file will break `require` or yield 404 for all /payments paths).

Current controllers/paymentController.js behavior:

POST /payments/start
  • No auth middleware in routes unless you add it in paymentRoutes.js.
  • Body (JSON) — both required or 400 { "message": "Missing payment details" }:
      { "userId": 2, "totalAmount": 165 }
    (cartItems in body is not used by the controller.)
  • Response: 200 JSON — message, paymentId, bitPaymentUrl (mock Bit URL).
  • If start fails at runtime, align models/paymentData.js with the controller (controller
    expects an array-like store with .push / .find, or change the controller to use addPending).

POST /payments/webhook
  • No auth (intended for provider → server callbacks).
  • Body (JSON): { "paymentId": "<string from start response>", "status": "success" }
  • Unknown paymentId → 404 JSON { "message": "Payment not found" }.
  • Known payment + status "success" → sets that payment’s status to "completed" and logs;
    it does not yet create an order or clear the cart (see TODO comments in controller).

CART (mounted at /cart)
--------------------------------------------------------------------------------
Cart owner is always the numeric user in header x-user-id (no user_id in URL or POST body).

Headers (all cart routes that need “whose cart”): x-user-role: user | admin | manager
  and  x-user-id: <numeric user id whose cart you are reading / adding to / clearing>
  (admin/manager: set x-user-id to the customer’s id when acting on their cart.)

GET cart (joined product name, image URL, current price on each line):
  GET http://localhost:3000/cart
  Headers: x-user-role: user, x-user-id: 2
  Response: { user_id, cartId, createDate, item_cart: [ { cart_item_id, id, orderId, productId, quantity, petImageUrl, createDate, product_name, product_image, price }, ... ] }
  If user has no cart yet: cartId null, item_cart [].

POST add line:
  POST http://localhost:3000/cart
  Headers: x-user-role: user, x-user-id: 2
  Body JSON: { "productId": 1, "quantity": 1, "petImageUrl": "http://localhost:3000/images/clients/my-pet.jpg" }

PUT update line quantity (routes/cart.js registers PUT only for /:item_id):
  PUT http://localhost:3000/cart/1
  Headers: x-user-role, x-user-id (must own the line’s cart unless admin/manager)
  Body JSON: { "quantity": 2 }

DELETE one line:
  DELETE http://localhost:3000/cart/1
  Headers: x-user-role, x-user-id (see cartController ownership rules)

DELETE clear all lines for that user’s cart:
  DELETE http://localhost:3000/cart/clear
  Headers: x-user-id: 2 (and role header)

  Common mistakes (you will see HTML "Cannot GET ..." from Express):
  - Do NOT use GET on /cart/clear or /cart/clear/2. Clear is DELETE only; there is no
    /:user_id on the path — use header x-user-id: 2 instead of .../clear/2.
  - Do NOT use GET http://localhost:3000/cart/1 to "get user 1’s cart". There is no such
    route. Use GET http://localhost:3000/cart with header x-user-id: 1. The path /cart/1
    is only for PUT/DELETE on line item id 1, not for loading the whole cart.
